# 1.1 确认需求与原始设计记录

2026-11-16 已确认并实施以下决策，交付验收结果见 [1.1 版本说明](RELEASE-1.1.md)。本次只在本地开发与隔离验收，不自动更新正式 ECS 或上传 GitHub。

- ECS SSH 身份与应用认证完全独立；应用不读取、挂载或绑定 ECS 私钥。真实连接资料只存本机私有目录，仓库提供模板。
- 加密密钥信封及结构版本存入数据库。新备份只有一个必需的 `.dump`，恢复仍需原主密码或恢复密钥；旧 `vault.json` 仅用于显式旧格式迁移。
- 源码与状态目录分离，默认状态目录 `/var/lib/wechat-vault`，可配置。新服务器生成自己的查询机器密钥，首次登录重新建立自动启动信封。
- 闲置 5 分钟、绝对期限 1 小时，不启用短租约。点击、输入、滚动上报活动；轮询和下载不续期。
- 切后台、离开、主动锁定及确认断网立即清屏并尝试撤销共享会话；恢复需要重新认证。晚到响应不能回填，微信查询继续运行。
- 明确离线立即清屏；其他故障两次探测确认（每次最多 3 秒、间隔 2 秒），普通请求最多 5 秒。
- 单生成任务、最多两条下载；生成超时 30 分钟、保留 7 天、配额 5 GiB、最低空闲 1 GiB，可配置。
- 当前已鉴权下载在锁定后继续，最多 30 分钟；新下载重新鉴权。首版不续传，中断后从头下载，不将开始下载称为本地灾备验证成功。
- 恢复先验证临时数据库，再备份并事务性替换目标；兼容旧双文件包。迁移验证凭据和全部密文，不重新加密业务数据。
- 验收使用合成数据和独立 Docker 数据库，验证超过 512 MiB 的实际下载、新机器密钥恢复、两种解密凭据、内存峰值、注销响应与真实存储/日志的密文边界。

当前操作指南见 [恢复指南](RECOVERY.md) 和 [运维说明](OPERATIONS.md)。**以下保留的是 1.0 阶段原始设计讨论，其中双文件新备份、待定时长和可选租约等内容已被上述决策取代，不作为当前操作步骤。**

2026-10-30 新增：**管理端网页发起全量备份，并下载到本地电脑用于云服务灾备**。备份和打包在云服务器执行，用户通过现有管理页面操作，无需手动登录服务器执行备份脚本。

## 1.0 当前行为

| 项目 | 当前行为与依据 |
| --- | --- |
| 会话有效期 | 登录后固定有效 8 小时，访问不会续期；没有按用户闲置时间锁定。见 [会话实现](../vault/web/sessions.py)。 |
| 主动锁定 | 撤销当前浏览器 Cookie 对应的管理会话，并清理该会话的微信绑定二维码；不会撤销其他独立浏览器会话。见 [会话接口](../vault/web/routes/session.py)。 |
| 关闭或切换页面 | `pagehide` 清理前端敏感状态，不请求服务器注销；切到后台只隐藏已显示的密码。关闭标签页或浏览器不能作为服务端已注销的保证。见 [页面生命周期](../vault/web/static/js/main.js)。 |
| SSH 断开或网络中断 | 不撤销管理会话。请求失败会提示连接错误；周期状态查询的错误被忽略，不因此清理当前页面数据。见 [请求处理](../vault/web/static/js/shared/transport.js)与[状态查询](../vault/web/static/js/main.js)。 |
| Cookie | 使用会话 Cookie，设置 `HttpOnly`、`SameSite=Strict`，未设置 `Secure`，适配 SSH 隧道末端的本地 HTTP。Cookie 的浏览器恢复行为不能替代服务端超时。见 [会话实现](../vault/web/sessions.py)。 |
| 管理锁与微信查询 | 管理会话与微信查询的权限生命周期分开，但使用同一运行时数据密钥。管理锁定只撤销管理权限，数据密钥继续支持微信查询；应用关闭时调用 `service.lock()` 清空运行时密钥引用。服务启动可使用已有机器密钥恢复查询，不创建管理会话。见 [应用生命周期](../vault/web/app.py)、[数据服务](../vault/core/service.py)与[安全说明](security/SECURITY.md)。 |

## 会话与锁定需求

| 编号 | 需求 | 建议规则 |
| --- | --- | --- |
| S1 | 闲置锁定 | 建议连续 **5 分钟**无用户操作后撤销管理会话。后端记录和判定有效期；自动状态查询、心跳、后台刷新及重试不计作用户操作，不延长闲置期限。 |
| S2 | 绝对有效期 | 建议登录后最多 **1 小时**必须重新认证；持续操作或心跳不能延长这一上限。 |
| S3 | 显式退出 | 保持主动锁定即撤销服务器会话，清理 Cookie 和前端敏感状态。撤销后，旧会话发起的管理请求必须被拒绝；不能只隐藏界面。 |
| S4 | 断网保护 | 在确认连接失效后清除已加载记录、已显示凭据、编辑内容及相关临时状态，并显示锁定界面。断网时注销请求可能无法送达服务器，仍由服务端期限限制旧会话；恢复连接后先完成会话核验或重新认证，再重新读取数据。连接失败的判定及恢复方式待确定。 |
| S5 | 可选的短租约 | 如需在关闭页面、休眠或失联后更快撤销会话，可增加心跳租约，建议最后一次有效心跳后 **60 秒**失效。该方案尚未选择；心跳仅维持在线租约，不续 S1 闲置期限或 S2 绝对期限。 |

所有管理接口必须执行服务端会话检查。前端计时和清屏用于减少页面暴露，不能替代服务端撤销。锁定前发出的延迟响应不得重新填回已清理的数据。

保持微信查询独立运行的现有边界：管理会话过期、退出或失联均不应调用全局 `service.lock()` 停止微信查询。若后续要求停止全部解密能力，应作为另一项明确需求评估。

## 断开与多页面语义

普通 HTTP/TCP 连接结束不等于用户退出；不能在每次连接关闭时锁定。页面关闭通知可能因断网、浏览器退出或进程终止而丢失，不承诺“关页面必定立即在服务端注销”。需要快速失效时，由已选定的服务端超时或短租约兜底。

实施前需确定：

- 用户活动的定义：点击、输入、阅读页面是否计入，如何排除自动请求。
- 最终闲置时长、绝对时长，以及是否启用短租约与其宽限时间。
- 多标签页共享 Cookie 时的策略：关闭一个标签是否退出所有标签，其他活跃标签是否维持会话，主动锁定如何同步清屏。
- 切后台、系统休眠、浏览器恢复及网络短暂波动的处理；若启用短租约，接受后台计时节流可能造成重新登录的取舍。
- 断网后的判定阈值、恢复时是否一律重新登录，以及未保存编辑内容如何提示和丢弃；不得为了恢复编辑而将密码等明文持久化到浏览器存储。

## 会话与锁定验收条件

以最终确认的时长和策略验收；先使用可控时钟与合成数据验证，不用真实密码记录作为测试内容。

1. 闲置到期后，旧 Cookie 调用读取、新增、修改、删除和设置接口均失败；持续状态轮询和心跳不能避免到期。有效用户操作只影响闲置期限。
2. 即使持续操作，达到绝对期限后仍需重新认证；重放旧 Cookie 不能恢复会话。
3. 主动锁定成功后，旧会话后续请求被拒绝；记录、凭据、编辑表单及临时绑定状态被清理，延迟响应不会重新显示数据。
4. 模拟断网和 SSH 隧道断开，按已选阈值清屏；在不能送达注销请求时，服务端仍会按期限失效。恢复连接不会直接显示旧页面缓存。
5. 覆盖多标签、关闭标签、浏览器恢复、切后台和休眠恢复；实际行为符合事先选定策略。若采用短租约，停止心跳后在租约期限内失效，心跳不延长闲置或绝对期限。
6. 管理锁定或超时后，已启用的微信查询继续工作；重新登录可恢复管理功能，不改变数据库数据或查询启动密钥。

## 管理端全量备份与本地灾备

### 目标与当前基础

在管理页增加“备份与灾备”入口：点击“生成全量备份”，服务器后台生成压缩包，完成后点击“下载到本机”，由浏览器保存到用户选择的下载位置。页面显示生成阶段、备份时间、文件大小、下载入口和失败原因；不能将“服务器已生成”或“已开始下载”显示为“本地灾备已验证”。

1.0 已有 [备份脚本](../ops/backup/backup.sh)和[恢复脚本](../ops/backup/restore.sh)，但没有网页备份接口。现有备份包为 `vault-backup-<UTC时间>.tar.gz`，包含 `database.dump` 和 `vault.json`。数据库使用 PostgreSQL 17，`pg_dump` 支持在线一致性导出，可作为后台生成任务的基础，见 [PostgreSQL 官方说明](https://www.postgresql.org/docs/17/app-pgdump.html)。不能直接复制运行中的 PostgreSQL 数据目录充当备份。

### 需求范围

| 编号 | 需求 | 规则 |
| --- | --- | --- |
| B1 | 网页生成全量备份 | 已登录管理端可发起后台任务，备份整个业务数据库，不受列表搜索、标签、分页或回收站视图影响；同一时间仅执行一个生成任务，重复点击不得启动多个导出进程。 |
| B2 | 配套灾备内容 | 包含数据库结构、全部表数据和序列，以及匹配的 `data/vault/vault.json` 密钥信封。覆盖有效记录、尚未清除的回收站记录、加密设置、加密查询日志、审计及消息去重状态。已从数据库彻底清除的数据不承诺找回。 |
| B3 | 大文件打包与下载 | 云端落盘生成完整归档后再提供下载，生成与下载分离。下载按块传输，服务端和浏览器脚本均不得把整个文件载入内存或转为 Base64/完整 Blob。断网后可重新登录并在文件有效期内重试下载；断点续传默认作为可选增强，但若最终会话规则会阻断大文件完成下载，则必须纳入，见下方实现约束。 |
| B4 | 完整性与格式兼容 | 仅成功生成的文件可下载；提供归档字节数、SHA-256 校验文件及应用/数据库/备份格式版本信息。优先保持包内仅含 `database.dump`、`vault.json`，校验与版本信息放在独立下载的说明文件中；若改变包格式，必须同步修改恢复工具并验证旧包兼容。 |
| B5 | 访问与数据边界 | 创建、查询状态、下载及重试均检查服务端管理会话，继续经 SSH 隧道访问；创建任务沿用 CSRF 防护。无公共下载链接，不开放数据库端口，不接受用户指定 Shell 命令或服务器文件路径。业务敏感内容保持原有密文，不导出明文密码表。 |
| B6 | 资源与文件生命周期 | 后台任务设置超时、磁盘空间检查和并发限制；失败不发布残缺文件。完成文件按明确期限保留，失败与过期临时文件自动清理；清理与正在下载的文件协调，不误删用户其他备份或本地副本。建议沿用云端 7 天保留上限，具体容量配额在实现时按服务器空间确定并展示。 |
| B7 | 可恢复性 | 配套提供新服务器恢复步骤，并用从网页下载的包在隔离环境完成恢复演练。“完整下载、校验通过、可恢复验证通过”是功能交付条件；网页上传并覆盖当前数据库的恢复入口不在本次需求内。 |

### 灾备包及恢复依赖

必须同时保存数据库与密钥信封；只有 `database.dump` 无法恢复加密密码库。`vault.json` 保存加密包装后的数据密钥，不包含明文主密码。用户需要在备份包之外妥善保存与该备份匹配的**主密码或恢复密钥**，两者均丢失时无法正常解密恢复。

归档不包含主密码、恢复密钥、SSH 私钥、机器密钥 `secrets/query-unlock.key`、查询启动信封 `query-unlock.json`、服务器 `.env`、运行日志或整台服务器文件。业务字段保持加密；表名、记录时间等数据库元数据并非全部加密，压缩打包本身不提供额外加密。加密字段及已有压缩数据的压缩收益可能有限，不承诺压缩比例。

本功能提供密码库的数据灾备。云服务器完全丢失时，使用另行保留的对应应用发布包、部署配置说明和备份文件，在新服务器重建运行环境，再恢复数据库与密钥信封。数据库角色由部署初始化脚本重建，模型文件可重新下载，内存向量索引由应用重建；无需恢复原服务器的机器密钥。首次登录后重新启用微信查询自动恢复，并检查微信绑定、通道令牌和 AI 设置；外部令牌失效时需重新绑定或配置。备份只覆盖导出快照中的数据，不包含其后的修改，不提供连续时间点恢复。

云端备份清理或数据库删除不会删除用户已下载的副本，本地副本由用户自行保管和轮换。本次范围为按需手动生成与下载，不自动安装定时备份任务。

### 实现约束与接口草案

- 建议接口：`POST /api/backups` 创建任务；`GET /api/backups/{id}` 返回生成中、就绪、失败或已过期状态；`GET /api/backups/{id}/download` 下载完整归档，另提供配套校验与说明文件。任务 ID 只用于定位服务端登记的文件，不代替身份认证，也不映射任意文件路径。
- 当前应用容器没有 Docker CLI、PostgreSQL 导出工具或宿主机备份目录挂载，且 `/tmp` 仅 16 MiB，不能直接从网页调用原脚本。实现时需选择受限的后台备份执行方式，配置与数据库版本匹配的导出工具及独立磁盘目录；不向 Web 容器授予宿主机 Docker socket 或任意命令执行能力。
- 尽量复用现有备份格式与恢复能力。网页任务、命令行备份、恢复及未来密钥变更必须协调互斥，确保数据库快照和密钥信封配套；长时间导出、压缩和下载不得一直持有业务全局锁，导致微信查询、管理操作或注销阻塞。
- 下载使用附件响应及 `Cache-Control: no-store`，不得进入静态资源目录或浏览器持久缓存。状态轮询和下载不延长 S1 闲置期限或 S2 绝对期限；管理会话失效后，后续状态/下载请求必须重新认证。已发起的长下载遇到超时或主动锁定时，是中止传输并在重新认证后续传，还是在有上限的传输授权内完成，需与最终会话规则一并确定；若选择中止且文件传输可能超过会话期限，必须将经认证的断点续传纳入 B3，避免大文件永远无法下载完成。已发送或缓冲的字节无法撤回；后台生成任务可以继续，重新登录后在保留期内领取结果。
- 云端生成任务与下载各自记录成功/失败及时间、大小等必要元数据，不记录备份内容、凭据、密钥或敏感命令输出。恢复指南必须说明校验方式、版本要求、部署依赖及首次登录步骤。

### 备份与灾备验收条件

全部使用合成记录与临时密钥，在隔离数据库/环境执行，不覆盖正式密码库。

1. 从管理网页发起、等待生成并下载到本机，归档大小及 SHA-256 与服务端结果一致；包内结构与恢复工具约定一致。损坏、截断、导出失败或密钥信封缺失的文件不得标为可用备份。
2. 包含有效记录、回收站记录、设置及各业务表数据；并发写入时数据库导出保持一致。并发备份、恢复或密钥变更不会产生数据库和密钥信封不配套的归档。
3. 在全新隔离部署中，仅依靠发布包、部署说明、下载的灾备包和用户另存的主密码或恢复密钥，恢复并验证记录解密、回收站、设置和日志。主密码和恢复密钥分别验证可用，错误密钥不能解密；不依赖原服务器机器密钥。恢复后管理端仍需认证，首次登录可重新启用查询自动恢复。
4. 未登录、已注销、过期会话、伪造任务 ID 或路径均不能发起下载；已开始的长下载按最终确定的超时/锁定策略处理。跨来源任务创建被拒绝；状态轮询不续期，重新登录可领取仍有效的已完成备份。覆盖传输耗时超过会话期限的情况，验证可以按已选策略完整取得大文件。
5. 使用超过应用内存限制的合成备份验证生成、打包与下载，内存占用不随整个文件大小增长；正常磁盘余量下微信查询与管理注销仍可完成。覆盖重复点击、磁盘不足、超时、应用重启和 SSH 隧道中断，失败有清晰提示且不发布残缺归档。
6. 失败临时文件与过期文件按规则清理，活跃下载不被清理误伤，本地已下载副本不受影响；文档明确断点续传是否支持以及中断后的重试步骤。
7. 解包后，使用 PostgreSQL 工具将压缩转储转为可检查的表示或恢复到隔离数据库，检查实际存储字段、密钥信封及运行日志；不能仅在压缩文件字节中搜索来判定没有泄露。上述存储内容不得出现合成的明文账号密码、API Key、主密码、恢复密钥或机器密钥；应用仍可使用正确凭据解密恢复。

## 访问方式：保留现状，备选另行决定

1.0 继续使用 SSH 隧道：浏览器访问本机 `127.0.0.1:18080`，经服务器 SSH 转发到服务器 `127.0.0.1:18080`。回环地址指各自机器，并非绑定用户电脑的某个固定局域网 IP；源码的本地主机检查也不代表硬件身份绑定。见 [容器配置](../compose.yaml)、[客户端配置](../client/console.psd1)与[请求边界](../vault/web/security.py)。

SSH 服务的 22 端口可以同时承载日常终端连接和管理隧道，不会因隧道而被独占。需要区分的是本机转发监听端口被其他程序占用；现有启动入口支持调整本地端口，见 [使用说明](../README.md)。

HTTPS 直接访问只是已评估的备选，用户尚未选择，不属于 1.0，也不因本文件自动开始开发。若后续选择，需另行确定域名与可信证书、反向代理、允许来源、登录限流，以及 `Secure` Cookie、Host/Origin 校验等边界；不能直接把现有 HTTP 端口暴露公网并仅依靠主密码或缩短锁定时间。会话改进可独立于访问方式实施。
