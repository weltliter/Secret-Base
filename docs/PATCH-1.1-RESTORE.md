# 1.1 上传数据库恢复补丁

日期：2026-11-17。应用版本仍为 1.1，数据库结构版本仍为 2，无需迁移数据结构。

管理端“备份与灾备”新增 `.dump` 文件选择、覆盖确认和“上传并全量恢复”按钮。恢复按备份完整替换账号、回收站、设置、消息去重状态、审计、查询日志、版本与加密密钥信封；没有增量合并。

上传受管理员会话、来源检查、CSRF、显式覆盖确认、磁盘配额和超时限制。数据流式写入私有文件，PostgreSQL 17 工具只展开数据；程序读取固定表和列的 COPY 数据，不执行上传内容中的 SQL。先在临时表验证完整性与兼容性，再事务性清空并写入全部应用表，审计序列也可回滚。失败不替换原数据库，临时文件会清理。应用数据库角色不需要新增权限。

成功后清除全部管理会话、旧查询启动信封和查询缓存。使用备份对应的原主密码或恢复密钥登录后重新启用查询。上传期间保持页面在前台，断线后重新登录核对结果。建议恢复前自行下载现有数据库备份。

本补丁只修改本地源码；没有部署到正式服务器。更新已运行的 1.1 时，先备份，使用补丁源码重新构建并更新应用容器；数据库结构和权限配置不变。详细使用步骤见 [恢复指南](RECOVERY.md)。

验证结果：

- PostgreSQL 17 独立测试容器中 181 项 Python 测试通过，使用无超级用户和无建库权限的应用角色。包括真实大于 256 KiB 的备份上传、不同密钥的密码库全量替换、全部应用表与审计序列恢复、原主密码和恢复密钥登录、损坏文件拒绝，以及删除、插入和修改序列后发生异常时的整体回滚。
- 18 项 Node 前端测试通过，包括文件及覆盖确认、原始文件传输调用、成功锁定和晚到响应丢弃。
- Edge 无头浏览器实际生成并下载备份，新增合成记录后上传恢复，重新登录确认该新增记录消失；验证恢复成功提示、文件输入清空、390px 布局无横向溢出、无页面脚本错误。

全部验证只使用本机独立合成数据库。未连接正式库，未调用微信或模型外部服务；本次没有重新执行旧版本的 512 MiB 以上备份性能验收。
