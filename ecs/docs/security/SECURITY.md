# 安全边界与数据处理

本项目为单人密码库，信任服务器运行时、独立机器密钥和持有 SSH 私钥的电脑。查询服务运行期间，应用可以在内存中解密数据；它不是服务器不可解密的零知识方案。整台服务器被控制时，机器密钥可被用于解密，数据库或备份单独泄露时业务数据仍为密文。

## 身份与网络

微信请求必须来自初始化时通过官方扫码绑定的唯一用户身份。身份检查先于模型调用和业务记录查询。微信控制器使用 QueryVault 只读能力接口，没有新增、修改、删除、恢复方法；传输游标和消息去重信息由程序内部维护。群聊、其他账号、消息正文里伪造的用户 ID 不获得访问权。绑定不采用“先发消息的人就是主人”的规则。

电脑管理页面依赖 SSH 身份验证、本地隧道和主密码登录后的浏览器会话。随机管理令牌存于 HttpOnly、SameSite=Strict 会话 Cookie，服务器仅在内存中保存令牌摘要、闲置期限和绝对期限；重启后所有管理会话失效。默认闲置 5 分钟、登录后绝对期限 1 小时，只有用户活动接口可续闲置时间；轮询和下载不续期。主动锁定撤销当前浏览器共享会话，同一 Cookie 的标签页同步清屏，其他独立浏览器会话不受影响；微信运行密钥和绑定不变。

页面隐藏、离开或断网保护触发后清除记录、凭据、编辑内容及临时状态，取消请求并拒绝晚到响应回填。离开通知可能无法送达，服务端期限负责兜底，不能承诺关闭页面立即注销成功。恢复前台或连接后需要重新认证。应用端口只发布到服务器回环地址；PostgreSQL 关闭 TCP 监听，仅提供给应用容器共享的 Unix socket。应用以内部角色 `vault_app` 连接。管理 API 检查请求来源，并对修改请求校验 CSRF Token。模型服务不能访问管理 API、Shell、数据库原始查询接口或任意网址。

ECS 私钥只被本机 SSH 工具读取，不上传给应用、不挂载进容器、不用于派生密码库密钥。数据库访问不绑定 ECS 实例、地址、SSH 用户名或密钥指纹。新 ECS 的连接身份与原应用主密码分别负责连接和解密；不能用新的 SSH 私钥替代原主密码或恢复密钥。

## 明文出现的位置

| 数据 | 允许出现明文的位置 | 持久化要求 |
| --- | --- | --- |
| 账号、密码 | 录入页、已解锁服务内存、用户主动要求的微信查询结果 | 数据库及备份中加密 |
| 私密备注、自定义字段 | 录入页、已解锁服务内存；不进入微信结果或模型请求 | 数据库及备份中加密 |
| 系统名称、网址 | 录入页、检索内存、DeepSeek 请求及微信查询结果 | 本项目持久化时加密 |
| 检索描述、标签 | 录入页、检索内存、DeepSeek 请求；不进入微信结果 | 本项目持久化时加密 |
| DeepSeek Key、微信通道令牌 | 解锁后的服务内存和对应官方 HTTPS 请求 | 加密保存，不写正文日志 |
| 主密码、解密后的数据密钥 | 解锁流程和服务内存 | 不写磁盘、数据库或日志 |
| 微信查询正文 | 通道处理、模型请求、短期会话内存、已登录管理端的查询日志 | 先遮盖已知秘密，再加密存入查询日志，保留 30 天、最多 2000 条 |
| 业务语义向量 | 云端服务内存 | 不持久化；重启后从加密描述重建 |

微信和 DeepSeek 属于外部服务。当前产品选择允许微信保存查询结果，并允许 DeepSeek 处理用户问题和明确标为可检索的描述。不能用本项目的加密承诺推断外部服务不会保存其接收到的信息。

自由备注和自定义字段默认属于机密；不能通过模型脱敏后再发送的方式处理原始秘密。只有显式指定的检索字段可以进入模型上下文。

## 加密与密钥

业务字段在数据库写入之前进行带认证的加密。每条记录整体作为加密载荷，携带独立随机 nonce，记录身份绑定到认证附加数据，防止不同记录之间替换密文。设置与密钥信封使用各自的用途标识，密钥信封保存格式版本。

主密码通过 Argon2id 派生包装密钥，用于解开随机数据密钥。1.1 的密钥信封保存于数据库 `vault_metadata`，包含盐、参数、版本和加密后的数据密钥，与业务密文在同一份数据库快照中备份。主密码与解密后的数据密钥不写盘，也不复用 SSH 私钥。离线恢复密钥必须由用户在备份之外保存。

正常运行不依赖旧 `vault.json`。显式导入旧包时验证原主密码或恢复密钥及全部加密内容，保留原始信封字节和业务密文；未知结构/加密版本、不同信封冲突或有数据却无信封时拒绝继续，不自动生成替代密钥。

程序不保存明文向量或能跨备份暴露密码相等关系的指纹。重复比较在已解锁服务器内完成，密码按原始值比较，不忽略大小写、空格或其他字符。相关索引只保留在查询服务内存，服务退出后失效；管理端注销不会停止查询。

为了重启后无需人工输入主密码，首次管理登录后，数据密钥另用随机机器密钥加密，写入状态目录下 `data/vault/query-unlock.json`；认证附加数据绑定数据库中原始信封字节的摘要。机器密钥位于同一状态根目录下独立的 `secrets/query-unlock.key`，只读挂载给应用，不进入镜像、数据库或备份。启动时验证密钥与数据库匹配再恢复查询，失败保持未就绪，不创建管理会话。新服务器生成新的机器密钥，恢复备份会删除旧查询启动信封，必须重新管理登录。

## 数据库备份与下载

新备份是单个 PostgreSQL custom-format `.dump`，包含整个业务数据库及加密信封。表名、记录时间等技术元数据未全部加密；压缩本身不是额外加密。机器密钥、查询启动信封、主密码、恢复密钥、SSH 私钥和实际服务器配置不进入备份。

任务创建、状态、下载、校验和说明接口均检查管理会话，创建请求检查 CSRF。任务 ID 仅索引服务端登记的文件，不是授权凭证，也不能选择任意路径。应用使用固定导出程序和参数，不接受用户提供的 Shell 命令，不持有 Docker socket。只有完整生成并校验的文件可下载，响应为 `no-store` 附件，按块传输。

下载开始时创建有上限的传输授权：已批准的当前传输可在管理端注销或超时后继续，最多 30 分钟，已发送字节无法撤回；新的请求仍需有效会话。下载与轮询不会续管理会话，不提供公开下载链接。文件过期清理避开活跃下载，用户下载到本机的副本由用户自行保管。

源码公开发布与数据备份分离。真实连接资料、运行状态、备份和密钥不提交到 Git；公开分支从经过核验的源码树建立干净历史，不能把只做当前树脱敏当成旧提交也已清理。

## 查询与删除

模型仅使用允许的描述字段和候选记录 ID。查询与允许的描述字段由同一个中文嵌入模型向量化，使用归一化向量的余弦相似度召回，再与关键词候选合并交给模型排序。默认最多 3 条、可指定 5 条；匹配不足时按语义距离补充候选，并明确标识为弱匹配，不把相似度当作正确率。明确违反用户排除条件的记录不会补回。最终账号密码由普通程序按验证后的记录 ID 读取并拼装，密码不进入模型请求或回答生成过程。模型输出中的未知 ID、越权工具请求和格式错误均不能直接触发机密读取或修改。

变动权限只在通过 SSH 隧道访问的电脑管理 API。微信即使收到绑定主人发送的删除、更新、恢复等指令，也不能执行写入。管理页删除需先确认，更新与删除通过记录版本防止覆盖较新的变动。

同一账号密码出现在不同服务，或凭据相同但备注存在差异，不能据此自动丢弃记录。在电脑管理页明确选择保留与删除对象。

删除先标记进入 30 天回收站，排除于普通检索及重复统计之外。到期清除当前数据库记录。旧备份依据保留周期清除，因此数据库删除不能承诺所有历史备份立即抹除，也不能宣称单条记录完成了密码学擦除。

## 日志与验证

容器运行日志只记录随机请求编号、候选和结果数量、向量状态、模型调用次数、固定错误码及耗时，禁止记录查询或响应正文、账号密码、API Key、通道令牌、主密码及完整模型上下文。管理端查询日志是独立的 `query_logs` 表：查询、结果名称与诊断内容整体加密，并将日志 ID 绑定到认证附加数据；不保存结果中的账号密码。数据库备份包含加密查询日志。写入日志失败只产生固定故障码，不阻止返回查询结果。浏览器不将业务内容写入 Local Storage、IndexedDB、Service Worker 缓存或 URL 查询参数。密码查询响应应使用 `Cache-Control: no-store`。

验证应覆盖：

- 错误主密码、损坏密文、记录间密文调换和管理端锁定后拒绝访问。
- 非绑定微信身份在模型调用之前被拒绝。
- 精确密码匹配与大小写、空格差异不会混淆；跨服务复用不会被自动删除。
- 微信变动指令无效果，电脑管理的确认、版本冲突和回收站恢复。
- 带唯一标记的密码不会出现在数据库转储、备份、日志和模型请求中。
- 提示注入不能获取机密字段、任意 SQL 或 Shell 能力。
- 管理端锁定、会话过期不影响微信；重启查询自动恢复且管理会话失效；机器密钥错误时拒绝自动恢复。
- 在新机器只使用源码、一个数据库备份、新 SSH 身份和原主密码或恢复密钥恢复，不使用旧机器文件；错误凭据、未知版本和迁移冲突失败关闭。
- 检查实际恢复后的字段与日志，不能只搜索压缩备份字节；覆盖超过 512 MiB 的流式传输、下载中注销和新请求重新认证。
