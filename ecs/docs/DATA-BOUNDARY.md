# 程序、数据库与 ECS 的边界

ECS 的 SSH 密钥只授权连接服务器。密码库主密码或恢复密钥只授权解密密码库。更换其中一套身份，不改变另一套身份。

| 层次 | 持久内容 | 放入 GitHub | 下载备份 | 换机处理 |
| --- | --- | --- | --- | --- |
| 通用程序 | Python、网页、部署工具、配置模板、固定依赖及模型校验值 | 是 | 不需要 | 获取匹配的发布版本 |
| 密码库数据库 | 记录、回收站、加密设置与日志、审计、去重状态、序列、加密密钥信封、格式元数据 | 否 | 单个 `.dump` | 恢复数据库 |
| 用户解密凭据 | 原主密码或 `recovery:...` 恢复密钥 | 否 | 不包含 | 用户另存，首次登录输入 |
| SSH 连接身份 | ECS 私钥、实际服务器地址、用户、已核对的主机指纹 | 否 | 不包含 | 配置新 ECS 的连接资料 |
| 查询自动启动 | 本机机器密钥、查询启动信封 | 否 | 不包含 | 新服务器生成机器密钥，登录后生成启动信封 |
| 可再生资源 | 公共模型文件、内存向量索引、临时备份任务 | 否 | 不包含 | 下载校验、重建或重新生成 |

应用容器不挂载 SSH 私钥。业务加密、登录、数据库查询和恢复不读取 ECS 地址、实例 ID、SSH 用户名或密钥指纹。客户端 SSH 启动器可以读取本机私钥以建立隧道，但它不是密码库的数据密钥来源。

## 单数据库恢复

1. 使用新 ECS 密钥登录新服务器，获取兼容的源码发布版本。
2. 初始化 Docker、数据库角色、运行目录、公共模型及新的查询机器密钥。
3. 导入用户保存的数据库转储。加密密钥信封与业务数据已经在同一份数据库快照内。
4. 通过新 SSH 隧道打开管理页，输入原主密码或恢复密钥。
5. 核对记录与设置，在新服务器启用查询自动恢复。外部微信授权失效时重新扫码，模型授权失效时重新配置。

SHA-256 文件和版本说明用于核验文件与兼容性，不是额外的解密钥匙。仅有新 ECS 私钥和数据库不能绕过应用主密码。原主密码与恢复密钥均丢失时，无法正常解密恢复。

## 1.0 兼容与回退

1.0 的数据库缺少加密密钥信封，需要原配套 `vault.json`。显式迁移验证凭据及加密数据后，将原始信封字节写入数据库；不重加密现有记录，不自动生成替代信封。

迁移之前保留旧数据库与旧信封的配套备份。回退 1.0 时同时恢复这两项及旧程序版本。Git 仅保存源码，不回退数据库、SSH 密钥或其他私有运行状态。

## 发布范围

本地基线历史用于回退，其中包含旧服务器的连接信息。公开发布从经过检查的当前源码树建立干净历史；不要推送本地所有分支、标签或使用镜像推送。`.gitignore` 只保护未跟踪文件，发布检查仍需核对实际跟踪清单和发布分支历史。

两端各自唯一的环境配置为 `admin/config.env` 和 `ecs/config.env`，不进入 Git、发布包或应用镜像。公开模板不包含真实地址、用户名、私钥路径或业务内容。主密码不保存；API Key 和微信授权在管理页设置后加密存入数据库，不混入环境配置。
